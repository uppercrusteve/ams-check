# 高原徒步助手

在高原上，先算今天净升了多少，再按 Lake Louise 量表自评一次。判断留在本机，不上传，不登录。

**打开就用：** https://uppercrusteve.github.io/ams-check/

装到手机桌面之后没信号也能开（Service Worker 预缓存整个页面）。

## 为什么做这个

上高原出事，多半不是体能问题，是节奏问题：一天拔太高，晚上还在往上睡。判断「今天升得算不算多」「现在这算不算高原反应」，靠记忆容易糊弄自己，尤其是累的时候。

所以这里只做两件机械的事：

1. 用昨晚睡眠海拔和今天最高海拔算净上升，超过通用建议线就明说。
2. 把 Lake Louise 量表的四项摆出来，按分数给结论。

## 怎么判

**上升速率**——海拔 2500 m 以上，睡眠海拔每日上升不超过 500 m 算正常，500–1000 m 算偏快，超过 1000 m 算过快。2500 m 以下不套这个限制。依据是世界山地医学学会（WMS）与 CDC 旅行者健康黄皮书的通用建议，不是针对个人的处方。

**自评**——Lake Louise 急性高原反应量表（2018 版），头痛、胃肠症状、疲乏虚弱、头晕四项各 0–3 分：

| 结论 | 条件 |
|---|---|
| 不像高原病 | 头痛 0 分，或总分 <3 |
| 符合 AMS | 头痛 ≥1 且总分 ≥3 |
| 中重度，考虑下撤 | 总分 ≥6 |

**红旗项**——静息也喘、咳粉红色泡沫痰、走路不稳、意识糊涂、休息一夜不缓解。勾上任意一项，页面直接判「立即下撤」。

## 它不干什么

- 不做诊断。评分是自评，不是医生的判断。
- 不考虑个人病史。心肺基础病、孕妇、儿童的实际阈值要医生另说。
- 不管地形、天气、负重和体能。同样 500 m，陡坡和缓坡不是一回事。
- 评分和人打架时，以人的状态为准。走不稳就下撤，别等分数凑够。

## 线路海拔

页面里附了雨崩、德钦—飞来寺、白马雪山三组参考海拔，点一下就能填进输入框。

**这些数字没有实测过**：来源是公开徒步路书和地形图上的高程点，标了核实日期（`src/routes.js` 顶部的 `ROUTE_VERIFIED`）。哪条明显不对，直接开 issue 或者改 PR，把用的图源和日期写上。

## 本地跑

页面用了 ES 模块和 Service Worker，`file://` 直接双击打不开，要起个静态服务：

```bash
python -m http.server 8000
# 然后开 http://localhost:8000
```

测试：

```bash
node --test "tests/*.test.mjs"
```

测试分两类：`tests/ams.test.mjs` 判阈值边界，`tests/shell.test.mjs` 查引用文件是否存在、缓存清单有没有漏、免责话有没有被删掉。

## 结构

```
index.html            页面
assets/style.css      样式
src/ams.js            纯计算：阈值、量表、建议（无 DOM，可单测）
src/app.js            DOM 渲染、localStorage、导出
src/routes.js         线路参考海拔
sw.js                 Service Worker，预缓存外壳
tests/                node:test
docs/methods.md       判定口径与出处
```

数据放 `localStorage`，键名 `ams-check.log.v1`，最多留 200 条，可导出文本。清浏览器数据会一起没。
