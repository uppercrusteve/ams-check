# 高原徒步助手

**[打开就用 →](https://uppercrusteve.github.io/ams-check/)**

上高原前算一下今天净升多少，到了营地按 Lake Louise 量表自评一次。纯前端，不登录，数据只在这台设备的 `localStorage` 里。

装到桌面后没信号也能开：Service Worker 预缓存了整个页面。手机上是这个形状：

```
昨睡 3200 m → 今天最高 4100 m
净上升 900 m · 上升偏快
自评 4/12 · 符合急性高原反应（AMS）
```

## 判据

**上升速率**：海拔 2500 m 以上，睡眠海拔每天升不超过 500 m 算正常，500–1000 m 偏快，超过 1000 m 过快。2500 m 以下不套这条。依据是 WMS 与 CDC 黄皮书的通用建议，不是针对个人的处方。

**自评**：Lake Louise 急性高原反应量表（2018 版）四项——头痛、胃肠症状、疲乏虚弱、头晕，各 0–3 分。

| 结论 | 条件 |
|---|---|
| 不像高原病 | 头痛 0 分，或总分 <3 |
| 符合 AMS | 头痛 ≥1 分且总分 ≥3 |
| 中重度，考虑下撤 | 总分 ≥6 |

**红旗项**：静息也喘、咳粉红色泡沫痰、走路不稳、意识糊涂、休息一夜不缓解。勾中任意一项，页面直接判「立即下撤」，跟分数无关。

## 线路海拔

页面里附了雨崩、德钦—飞来寺、白马雪山三组参考海拔，点一下填进输入框。

**这些数字没有实测**，来源是公开路书和地形图高程点，核实日期写在 `src/routes.js` 顶部的 `ROUTE_VERIFIED`。哪条明显不对，带上图源和日期开 issue，或直接改 PR。

## 本地跑

用了 ES 模块和 Service Worker，`file://` 双击打不开，得起个静态服务：

```bash
python -m http.server 8000   # 然后开 http://localhost:8000
```

跑测试：

```bash
node --test "tests/*.test.mjs"
```

`tests/ams.test.mjs` 盯阈值边界，`tests/shell.test.mjs` 查引用文件在不在、预缓存清单漏没漏、免责话有没有被人删掉。

## 它不干什么

- 不做诊断。分数是自评，不是医生的判断。
- 不认个人病史。心肺基础病、孕妇、儿童的实际阈值要医生另说。
- 不看地形、天气、负重、体能。同样 500 m，陡坡和缓坡不是一回事。
- 分数跟人的状态打架时，以人为准。走不稳就下撤，别等分数凑够。

## 结构

```
index.html            页面
assets/style.css      样式
src/ams.js            纯计算：阈值、量表、建议（无 DOM，可单测）
src/app.js            DOM、localStorage、导出
src/routes.js         线路参考海拔
sw.js                 Service Worker，预缓存外壳
tests/                node:test
docs/methods.md       判定口径与出处
```

历史记在 `localStorage` 的 `ams-check.log.v1`，最多 200 条，可导出纯文本。清浏览器数据会一起没。
